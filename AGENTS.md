# Project Instructions

## Project

Учебный веб-проект для поиска команд и участников.

Технологический стек:
- Backend: Node.js, Express
- Database: PostgreSQL
- ORM: Prisma
- Database hosting: Supabase
- Frontend: React
- API testing: Postman

Перед выполнением задач необходимо проверить фактическую структуру проекта и используемые технологии.

## General Rules

1. Общаться с пользователем на русском языке.
2. Перед работой изучать только необходимые файлы проекта.
3. Не изменять файлы, не относящиеся к текущей задаче.
4. Не выполнять действия за пределами предоставленных полномочий.
5. Не передавать задания другим агентам без прямого разрешения пользователя.
6. Не запускать других агентов автоматически.
7. Не выполнять Git push, merge, rebase или deployment без разрешения.
8. Не изменять production-конфигурацию.
9. Не раскрывать секреты, токены и содержимое `.env`.
10. Не выполнять разрушительные операции с базой данных.
11. При обнаружении серьёзной проблемы сообщать пользователю.

## Agent Roles

В проекте предусмотрены три роли:

- ANALYST — анализирует реализацию и составляет технические задания.
- DEVELOPER — реализует только явно порученные изменения.
- TESTER — проверяет функциональность, API и безопасность.

Роли не имеют права самостоятельно инициировать работу друг друга.

## Approval Policy

Пользователь является единственным координатором.

Любое техническое задание, созданное ANALYST, сначала передаётся пользователю.

DEVELOPER не имеет права приступать к реализации только на основании отчёта ANALYST.

TESTER не имеет права самостоятельно исправлять обнаруженные ошибки.

Любое расширение первоначальной задачи требует согласования.

## Coding Standards

- Соблюдать существующую архитектуру.
- Использовать понятные названия переменных и функций.
- Не добавлять зависимости без необходимости.
- Не изменять публичные API без согласования.
- Обрабатывать ошибки и проверять входные данные.
- Не создавать лишних абстракций.
- Предпочитать минимальные и проверяемые изменения.

## Reporting

Каждый агент обязан завершать задачу отчётом.

Отчёт должен содержать:
- Что было проверено или выполнено.
- Обнаруженные проблемы.
- Результаты работы.
- Необходимые дальнейшие действия.
- Ограничения и непроверенные предположения.

Не выдавать предположения за подтверждённые факты.
